# 项目执行纪律（三方共同遵守）

> **读者**：执行方（DSH）＋ 红队（Kimi／Qwen）＋ 决策方
> **性质**：这不是"建议"，而是本项目**已经用事故换来的规则**——每条都标注了它是被哪次事故逼出来的。
> **怎么用**：红队用它审执行方（**包括审 DSH 是否违反本文件**）；执行方用它自查；决策方用它验收。
> **违反的处理**：如实登记到 `PROGRESS_SYNC.md`，并补一道机械检查（见 R4）。

---

## 一、诚信类（**不可协商**）

| # | 规则 | 由来 |
|---|---|---|
| **R1** | **不伪造、不夸大、不诱导**。不利结果照样报告（如 v2 并不优于 v1、三项 DoD 未达标） | 全程底线；红队两轮击中"叙事透支" |
| **R2** | **区分"LLM 口径"与"人工口径"**，引用覆盖类数字必须带"未经人工校准" | 分类主题曾被误标为"人工分类" |
| **R3** | **不可比的数字不得排成上升线**（初赛 0.37／复赛 0.6871／决赛 0.7220 语料与验证集均不同） | 附录 C 第 7 条撤回该叙事 |
| **R4** | **"未核验"必须显式标注**（如 IEC/AES 条款未核验 → 不得声称合规） | 外部侦察制度化 |

## 二、证据类

| # | 规则 | 由来 |
|---|---|---|
| **R5** | **每条结论附可复跑命令或文件路径**；不写行号（文件在变），用 ID／路径 | 总线协议；红队引用错误事件 |

## 三、代码与生成物

| # | 规则 | 由来 |
|---|---|---|
| **R8** | **生成器必须保留人工数据**：重跑不得清空人填字段；仅显式 `--force` 才覆盖；写前备份、原子写 | 红队指出 `make_gold_set_notes.py` 重跑即**静默清空**判定（最高风险） |
| **R9** | **手改内容不得放在会被覆盖的生成物里**；更正写进**耐久勘误**文件，生成物只留指针 | SPIKE-12：竞品更正落在 `ppt_text_dump.md`（导出物），重跑即丢 |
| **R10** | **先验证后写盘**：补丁脚本必须 `ast.parse` 成功再 `write` | 我一次把 `write()` 写在 `ast.parse()` 之前，导致工具文件损坏 |
| **R11** | **只解析数据行**：表头／引用块（`>`）／代码块／表格说明里的数字**不得**当数据 | 未填答题卡被解析出 2 条假判定（未落库，干跑抓到） |
| **R12** | **死代码也是缺陷**（被读却未用的变量会掩盖静默降级） | 红队指出 `reconcile()` 读了 CSV 却从未使用 |
| **R13** | **文档声明必须与实现一致**（写"可断点续填"就得真能续填） | 同上事件；与 SPIKE-12 同类 |

| # | 规则 | 由来 |
