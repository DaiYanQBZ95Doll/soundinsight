# N6 评审风险清单（追问点与三段式答法）

> **用途**：线上评审/路演时可能被追问的**风险点**及其答法（每问三段：**承认事实 → 给出证据 → 说明边界或处置**）。
> **与 N5 的关系**：N5 是"口径卡"（数字怎么读），N6 是"风险卡"（弱点怎么答）；两者互补，不重复。
> **纪律**：答法中的每个数字都可在仓库复算；不辩解、不淡化。

---

## 风险 1｜"你们的模型指标只有 0.72，凭什么说有用？"

- **承认**：0.72 的 F1 在均衡任务里确实不算高。
- **证据**：本任务正例占比 **1.28%**，随机水平 F1 = 0.0248（平凡上界）——0.7220`[v2]` 是随机水平的
  **29 倍**；同任务最强传统基线 SVM 0.497、LR 0.410，本项目相对 SVM **+45%**，Welch t 检验 p=0.000932。
- **边界/处置**：绝对 F1 不可跨任务比较（均衡任务随机 F1 约 0.30–0.40）；我们把"可用性"落在
  **成本与召回**上：本地 1.763 s/1,000 条、高召回档 R 69.5%，配合置信度三档给出人工复核接口。

## 风险 2｜"训练和验证标签都是同一个 LLM 做的，这不是自证吗？"

- **承认**：是，这是**共享教师偏差**，我们没有全人工金标准。
- **证据**：弱标注精度 51.8% 经 LLM 逐条复核清洗至人工抽查 **78%**；剩余标注噪声 **9.1%**
  （Wilson 95% CI 5.6–14.5%，人工终审 15/16）；**无第二标注者**，因此算不了 κ/α——这一点写进了主文档附录 B。
- **边界/处置**：可提升方向是引入第二人工标注者（成本约 X 人时，未开展）；在此之前，我们把偏差**量化并披露**，
  而不是声称"标签干净"。

## 风险 3｜"长文本 68.3% 没达到你们自己定的 70%，算失败吗？"

- **承认**：按该验收线，**未达标**，我们如实记录。
- **证据**：窗口 128→512 截断桶召回**始终 51.2%**（TP21/FN20 完全一致）→ 推翻"截断是主因"；
  切窗推理把该桶召回提到 **82.9%**，但整体 F1 由 0.7206 降至 0.6034；约束式分档阈值下 **68.3%**。
  机制是"子片段信号被整篇平均"。
- **边界/处置**：下一步是**切片级打分 + 学习式聚合**（不是继续放宽窗口）；该结论本身即一次
  有价值的能力边界测绘。

## 风险 4｜"没有真实用户用过，业务价值是不是空的？"

- **承认**：**未开展真实卖家试用**（客观原因：无跨境电商渠道）——这是最大的价值主张缺口。
- **证据**：目前支撑来自可复算的**成本与吞吐**：本地 GPU 1.763 s/1,000 条（CPU 28.4 s）、
  零 API 费用；对照人工 8 小时/1,000 条（**假设口径**）。这些是工程事实，不是用户证言。
- **边界/处置**：把"真实用户验证"列入下一步并说明前置条件（需要渠道）；材料中**不出现**任何虚构证言。

## 风险 5｜"用 LLM 就能做，为什么需要你们训模型？"

- **承认**：通用 LLM 确实能做零样本判断，我们也做了对照。
- **证据**：同 1,000 条子集上 qwen3.7-plus 零样本 F1 0.9149`[v1 对照]`、deepseek-chat 0.9400`[v1 对照]`
  ——**都高于我们的 0.6871**；但代价是**单次 1,000 条即约 155,514 tokens**（qwen 零样本；其三种提示设置
  合计 **490,747** tokens），且数据需外发、延迟受网络与配额影响。
- **边界/处置**：我们卖的不是"更准"，而是**本地、零外发、可批量、成本可预测**；
  对数据敏感的卖家，这是硬约束。（对照数字含"循环性红利"声明，见 `llm_baseline.md`。）

## 风险 6｜"阈值 0.9744 / 0.6 看起来是硬凑的？"

- **承认**：阈值是**扫描选出来的**，不是理论值。
- **证据**：v1 的 0.9744 与 v2 的 0.6 各自在其**调参划分**上扫描得到（v2 走 tune/test 分离）；
  阈值扫描表在 `v2/w5_final.md`（0.05–0.95 全表）与 `results_summary.md`。
- **边界/处置**：我们同时披露 v1 的**同集选阈值偏差**（含乐观偏置）与 CV 波动随口径的变化
  （3.9% vs 5.7%）——这是方法学透明，不是掩盖。

## 风险 7｜"评测泄漏是怎么回事？会不会影响你们复赛提交的数字？"

- **承认**：v1 的 `val_v2` 与当前标签集划分重叠 79.5%（正例 78.9%），是我们自己发现并披露的。
- **证据**：在 `val_v2` 上评估当前标签训练的模型会虚高（实测 0.9126，**该数字作废**）；
  修正后同模型为 0.7206。
- **边界/处置**：**v1 已提交的 0.6871/0.6241 仍然有效**（当时划分一致），只是**无法由当前文件复现**；
  v2 起一律用当前留出划分，并写入机械检查。

## 风险 8｜"代码/老师/团队只有一个人，可持续性如何？"

- **承认**：单人团队（队长兼全部角色），这是真实约束。
- **证据**：为对抗这一点，我们把**过程机械化**了：数字审计 全部检查项（当时 211 项；以 `number_audit.md` 为准）检查、负向自测 15 项、
  仓库卫生扫描（密钥 0 含历史）、预提交守卫、AI 交接包（`AI_HANDOFF/`）、状态同步文件——
  换人接手只需读三份文件（README / AI_HANDOFF / PROGRESS_SYNC）。
- **边界/处置**：单人意味着**并发能力有限**（本轮已出现 GPU 串行排队）；下一步优先补的是
  "可交接性"而非功能数量。

## 使用说明

- 每问按"承认 → 证据 → 边界"三段作答，**不要跳过"承认"**——评委最反感的是辩解；
- 数字若被追问来源，直接指向仓库文件（评委可要求现场打开）；
- 本清单与 `docs/N5_qna_factbase.md`（口径卡）配套使用：**N5 管读数，N6 管风险**。
