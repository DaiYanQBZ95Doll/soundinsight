## §1 项目是什么（30 秒）

**SoundInsight**——面向**跨境电商耳机卖家**的音质差评**自动识别 + 五类问题归因**系统。

- 链路：`10 万条真实评论 → RLCA 两阶段标注（规则初筛 + LLM 复核）→ DistilBERT 二分类 + 五类多标签归因 → Agent 报告 / Gradio UI / HTTP API / 在线创空间`
- 目标用户：中小卖家（<10 人、无专职数据分析师）
- 价值主张：把人工 8 小时/千条的差评梳理压到秒级（GPU 实测 1.76 秒/1000 条），且**本地推理、零第三方 API**
- 团队：**更新世界的锋芒**（队长 黎同竣，个人参赛）
- 三阶段：**初赛**（可行性：5,000 条 / 63 正例 / F1 0.37）→ **复赛**（工程性：10 万条 / 1,280 正例 / F1 0.6871，已提交冻结）→ **决赛**（可信性：重训与无泄漏评估、校准、边界测绘、验证体系）

> ⚠️ 三阶段的指标**不可排成上升线**（语料、验证集、正例数、阈值规则全不同）。详见
> `docs/three_stage_comparison.md` §3.1。

## §4 口径纪律（**审阅前必读，这是最容易误判的地方**）

### 4.1 三代口径不可混用

| 代际 | 语料 | 验证集 | 报告值 | 状态 |
|---|---|---|---|---|
| 初赛 | 5,000 | 1,000 条（13 正例） | F1 **0.37** | 正例过少、阈值不可用 |
| **v1**（复赛已提交，**产品实际在用**） | 100,000 | `val_v2` 20,000（251 正例） | F1@调优(0.9744) **0.6871**、F1@0.5 0.6241 | 当时划分内有效，**现已不可复现**（文件重建）；且**用当前文件评估会泄漏**（实测 val_v2 有 79.5% 落在当前训练划分内） |
| **v2**（决赛候选，**不入包**） | 100,000 | `val_v3_test` 10,000（128 正例） | F1@调优(0.6) **0.7220**、PR-AUC 0.7811 | 构造上干净（训练/测试按当前文件划分互斥）；**权重按 hash+命令登记，不入提交包** |

**三条硬规则**：
1. **v1 与 v2 不可直比**（样本集不同）；且**同基准实验显示差异统计上不可分辨**（v1 0.7759 vs v2 0.7220，CI 重叠、点估计偏向 v1）→ **本项目不主张 v2 优于 v1**；
2. **引用阈值必须成对**：同一模型的精确率/召回率在不同阈值档下不可混用；
3. **产品跑的是 v1 权重**（`config.json` → `sound_model/` + `multi_label_model/`，`max_len: 128`）——不能说"产品已达 0.7220"。

### 4.2 覆盖数字必须带限定词

覆盖总量 **2,461（严格–严格，52.0%）／2,826（宽松–宽松，45.3%）** 是
**LLM 口径、未经人工校准**（分类主体是**执行方 AI**，不是人；独立人工金标**尚未执行**）。
对外引用**必须**写成"LLM 口径，未经人工校准"。

### 4.3 证据强度分级

- **强**：密码学哈希（`hashes.txt` 中的 SHA256、包内双向核对）；
- **弱**：文件 mtime 等时间戳（可被 `touch` 改写）——本项目**已降级**为辅助观察；
- **代理**：模型测量（如"闸门外判正率 0.03%"）——**不能替代直接测量**，本项目有活例：模型说 0.03%，LLM 实测 1.33%，前者是模型盲区。
