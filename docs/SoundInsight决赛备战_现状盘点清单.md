## 一、还没做好的部分（缺憾与硬伤）

### 模型与数据层（按严重程度排序）

**1. 高音维度 F1 = 0.00【最大硬伤】**
- 多标签归因五个维度中，"高音"完全失效（多标签 epoch4 实测）
- 风险场景：评委现场上传高音类差评，归因模块整体可信感受损
- 根因推断：该类正样本过少

**2. 最佳阈值 0.9744 过于极端**
- 校准良好的分类器不应在贴近 1.0 的阈值上才达到最优（F1 = 0.6871 @ thr=0.9744）
- 模型输出概率置信度虚高，校准（calibration）环节缺失或不完善
- 参照：thr=0.5 时精确率仅 47.9%（数字本身诚实，但分布形态暴露问题）

**3. 正例底盘过薄**
- 清洗后正例 1288 条；测试集真实正例约 250 条（thr=0.9744 时 TP=179）
- 统计功效上限被样本量锁死：显著性检验能过，但提升空间有限

**4. 弱标签同源偏差（shared-teacher bias）**
- 标注清洗与后续环节使用同一族大模型，标注偏差可能与模型偏差同向
- 审计文档已自行标注该风险，但未做消偏实验
- 懂行评委的预设提问点

**5. 文档口径松散【低危但修复成本极低】**
- 正例数 1257 与 1288 并存；摘要行混用两个阈值的指标；PDF 字节数、文件数与实测不符
- 包内 number_audit.md 本身是干净的；问题在复盘文档沿用旧口径
- **决赛主文档必须全部回归已验证口径**

### 交付层（对照决赛模板的缺口）

**6. 业务价值章节近空白**
- 复赛包强项在技术严谨；决赛模板第三部分（痛点、场景、可量化价值、市场规模）为业务侧评审核心依据
- 需从零撰写，且要把技术指标翻译成业务语言

**7. 演示视频（3-5 分钟）未做**
- 决赛新增交付物，零存量

**8. 百炼模型调用表待核对**
- 模板要求列明百炼模型标识、用途、调用方式
- 需确认 LLM 环节所用模型与通道，如实填写

**9. Demo 可运行性待复验**
- 环境已变更，Demo.zip 需在新环境重新验收（依赖链、api_server.py 等）

## 二、期望可以做好的部分（延伸与期许，按性价比排序）

**1. 阈值分班（per-class threshold）治高音失明**
- 五个标签各自调阈值，高音类单独放宽
- 成本约 1-2 小时；硬伤 #1 降级为"已识别边界 + 已有处置方案"，叙事反而加分

**2. 补校准环节（Platt scaling / isotonic regression）**
- 将最优阈值拉回正常区间，并产出校准曲线图
- 该图是"真正懂机器学习"的无声证明，50 强中能做者不多

**3. 审计方法论升格为核心卖点**
- 现有资产：number_audit.md、显著性检验、不利证据留存流程
- 叙事升级：从"差评分类器"到"**让 AI 分析结果可被审计的工作流**"
- 同赛道对手（ReviewMine、Review2Product、VOC Radar 等）简介中均未见此类能力

**4. 人工复核闭环量化**
- 已有人工复核 CSV；量化"AI 初筛 → 人工复核 → 复核一致率"流程
- 直接回应模板"可量化价值"要求（如差评处理人工成本降低 X%）

**5. 从分类到建议（Agent 链路延伸）**
- 现状：链路止于五维度归因；延伸：Agent 自动生成改良建议
- soundinsight_agent.py 骨架可能已具备，接通后写入使用流程

**6. 品类可迁移性论证**
- 现为蓝牙耳机单品类；论证"换品类仅需替换 XX 模块"
- 回应模板"规模化复制潜力"项，不必做真实验，论证即可
