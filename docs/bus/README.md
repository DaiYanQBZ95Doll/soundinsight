# 三方沟通总线（读我 30 秒即可）

> **为什么有这份文件**：此前三方都用大段文字表达，决策方阅读成本过高。
> 现改为：**意见一律落成"卡片文件"，沟通靠引用卡片 ID**，聊天窗口只发一句指针。

---

## 一、文件布局（防并发冲突）

```
docs/bus/
  README.md            ← 本文件（协议，谁都可以读，但只在裁定后由执行方改）
  INDEX.md             ← 自动生成的总览（**不要手工编辑**；跑 make_bus_index.py）
  TEMPLATE.md          ← 卡片模板（照抄即可）
  round-01/
    dsh.md             ← **每个作者一个文件**，文件名 = 作者名
    kimi.md
    qwen.md
  round-02/            ← 新一轮就新建目录，旧轮只读
    ...
```

### 并发规则（决策方会同时群发，务必遵守）

| 规则 | 说明 |
|---|---|
| **一人一文件** | 只写 `round-NN/<你的名字>.md`；**永不编辑别人的文件** |
| **一轮一目录** | 决策方群发一次 = 一轮；新轮新建目录，**旧轮只读**（避免读到半改写的状态） |
| **回应靠引用** | 要回应别人，就在**自己文件里**写 `re: kimi.md#K-3`（用 ID，不用行号） |
| **结论必须有 ID** | 形如 `DSH-1`、`KIMI-2`、`QWEN-3`；后续引用、裁定、闭环都用 ID |
| **不要改 INDEX** | 它是生成物；跑 `python make_bus_index.py` 刷新即可 |
| **基线声明** | 每张卡片顶部写明所依据的 HEAD（文件名/命令以**路径**引用，不写行号，因为文件在变） |

---

## 二、卡片格式（**目标是"一眼看懂"**）

见 `TEMPLATE.md`。硬性要求：

1. **TL;DR 不超过 5 行**，且必须能独立读懂；
2. 其余内容**一律用表格**（结论表 / 请求表 / 反对表）；
3. 每条结论必须带**证据指针**（文件路径或可复跑命令），**不接受无证据断言**；
4. 长论证请放到**附录**（同一文件末尾），正文只留结论；
5. 单张卡片建议 **≤120 行**；超了就拆成 `dsh.md` + `dsh-appendix.md`。

## 三、决策方视角（这份协议为你服务）

| 你想做的事 | 怎么做 |
|---|---|
| 一次看三方观点 | 打开 `docs/bus/INDEX.md`（一屏内列出三方 TL;DR） |
| 让三方就某点对齐 | 群发一句：「看 `docs/bus/round-01/*.md` 的 `<ID>`」 |
| 裁定 | 在 `INDEX.md` 之外的**你的裁定文件**里写一行（执行方负责落库），或直接口头说，执行方按 ID 记录 |
| 检查是否有新进展 | `git log -1 --stat` 或直接问执行方「刷新 INDEX」 |

## 四、执行方承诺

1. 每轮把我的意见写成卡片（不再发大段文字）；
2. **自动生成 INDEX**（含三方 TL;DR、卡片 mtime、基线 HEAD），并对"卡片比 INDEX 新"的情况报警；
3. 所有裁定按 ID 落到 `docs/frozen_execution_checklist.md` 与相关材料，**可机械核对**。
