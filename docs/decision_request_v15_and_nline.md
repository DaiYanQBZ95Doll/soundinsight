### 3. 程序问题定性（执行方自陈）

- 两项都是**在执行过程中先做、后登记**——按契约应先提请复审并升版；
- 两项**均系事故响应**（数据泄漏、误入库），不是范围扩张或功能追加；
- 但**程序就是程序**：未先升版即新增，属实。执行方**承认违规**，不辩解；
- 该项违规与本轮另一类问题（W4 取样错误、分类主体措辞）**并列登记**，未隐藏。

### 4. 三个选项与各自后果

**A. 追认** → 清单正式升为 **v1.5**，两项转为合法在册项；版本历史补一行。

**B. 追认 + 附加条款（执行方建议）** → 在 A 基础上增加两条约束：
1. **今后新增项「先升版、后执行」**（无决策方在线时，执行方**只登记为待办**，不实施）；
2. **新增一条机械检查**：核对清单声明的基准版本与「锁定后新增项」是否一致（当前靠人眼，本轮就是靠红队发现的）。
   *注：这条检查本身也是新增工作项，故须随本议题一并批准后才实施。*

**C. 否决** → 两项标记为「**执行方越权新增**」，并从清单移除。**但请注意回退的真实代价**：

| 若删除 | 后果 |
|---|---|
| 删 W6b | 等于**删掉一条真实且重要的事实**（泄漏确实发生过）。泄漏不会因为删除披露而消失，删掉只会让材料**更不可信** |
| 删 E7 | 等于**移除防凭据入库／防超大文件入库的守卫**，把已发生过的两类事故重新暴露 |

因此若选 C，执行方建议表述为「**保留产物，但记为越权新增并降权引用**」——
即：产物继续存在，但材料中不得据其主张程序合规。

### 5. 执行方建议（仅为建议）

**选 B。** 理由：两项产物本身是**降低风险**的（一个披露泄漏、一个防事故），

第 2 条把"靠人眼发现"变成机械检查，符合本项目"每起事故都机械化"的既有做法。

## 议题二：N 线交接协议去留

### 1. 协议是什么

`docs/N_line_handoff_protocol.md`（11,349 B，2026-09-30 由桌面端顾问提议、执行方核对后落库）：

> **用途**：规定「执行方 → 决策方（总线）→ 外部顾问（桌面端）→ 执行方」这条叙事线交接链路的
> 触发条件、输入格式、产出形态与落库流程。

- **触发条件**：W15（型号聚合）／W16（星级分层）产出素材，或任何 W 线包产出可用于叙事的实测数字；
  触发后执行方写 `docs/N_line_brief.md` 并在 `PROGRESS_SYNC.md` 标「待总线取件」；
- **链路**：① 执行方写 brief → ② 决策方（总线）取件并转发给外部顾问 → ③ 顾问起草 → ④ 执行方落库。

### 2. 实际发生（核实结果）

| 事实 | 核实 |
|---|---|
| 协议**从未被触发** | 决策方未发出总线路由指令 |
| `docs/N_line_brief.md` **从未创建** | 文件不存在 ✓ |
| `PROGRESS_SYNC.md` 中**无**「待总线取件」标记 | 检索命中 0 ✓ |
| N 线实际交付方式 | **执行方直接起草**：N1/N1b 框架（6.5 KB／7.2 KB）、N2 定稿草案、N3 校准证据组、N4 靶点论证与迁移协议、N5 事实底稿（17 问）、N6 风险清单（8 问三段式） |
| 定稿权 | **仍在决策方**（N2 中已标注需要决策方选定的措辞位置） |

### 3. 三个选项与各自后果

**A. 启用** → 恢复"总线路由 + 外部顾问起草"流程。
**但当前无适用对象**：N 线六份材料**已交付**，没有待起草的叙事任务；
若启用，唯一有意义的用法是**请外部顾问对 N2（含 v2 数字的主线）做一次独立复核**——
那时应重建 brief（原 brief 从未存在）。

**B. 废止（执行方建议）** → 文件标记「**已废止**（2026-10-01，决策方裁定）；如需再启用须明确指令」，
并从流程材料中移出，避免红队指出的"**悬空状态污染后续交接判断**"。

**C. 维持休眠** → 保留现状（文件内已写明"从未触发／休眠，待裁定"）。
代价：状态仍不确定，后续任何人读到时都要再判一次——红队已明确指出这是问题。

### 4. 执行方建议（仅为建议）

**选 B（废止）。** 理由：协议的唯一消费者（叙事起草）已由执行方直接完成，且**定稿权在决策方**这一点未变；
保留一个永不触发的协议只会增加交接歧义。若决策方希望外部顾问复核 N2，那是一次**新的具体任务**，
按议题一 B 的第 1 条"先升版后执行"办理即可，不需要复活整套协议。
