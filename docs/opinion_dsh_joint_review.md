## 1. 外部侦察结果（本轮新做，全部经实测）

### 1.1 ⚠️ 竞品格局已变——我方旧表述被外部事实推翻

- [Shulex VOC.AI](https://www.shulex.com/)：跨境电商**评论分析 + AI 客服**平台，官网列示
  **ANKER／SONGMICS／eufy／ESR／GameSir／Navimow 等 100+ 头部品牌**，提供 Agent 问答、**API/MCP 接入**、VOC 看板。
- [Skieer VOC](https://chromewebstore.google.com/detail/skieer-voc/bcniifmdiagmbieijjpmnlfnbhimcmde)：
  浏览器插件形态的评论分析产品。
- **结论**：我们材料里「Helium 10 与 Jungle Scout 仅提供通用情感分析，无法识别声学维度问题」这句话
  **不充分**——通用工具之外，已存在**专门的 VOC 平台**。
- **修正后的差异点（只能这么说）**：① **声学专项五类归因**（竞品未公开此类声学维度分类）；
  ② **本地推理／零 API 成本／数据不出境**；③（规划中）**与客观频响挂钩**。
- **不能说**：「我们比竞品更准」——**从未做过同数据集对比实测**。
- **已落地更正**：`ppt_text_dump.md`（竞品页加外部核验注）、`qna_preparation.md`（Q9 重写）。

### 1.2 外部独立验证：找了，但**量不够**（重要负面结论）

- 目标：找一个人工标注的公开数据集，替代"自己标自己测"。
- 找到：[SemEval-2014 Task 4（ABSA 经典基准）](https://aclanthology.org/S14-2004.pdf)，GitHub 镜像可达
  （HF 实测**不可达**，连接超时）。
- **实测结果**：Laptop 训练金标 3,045 句／2,358 个 aspect，其中**声学相关仅 46 条（37 负向）**；
  测试文件我解析到 0 条声学 aspect（格式差异或确实稀少）。
- **结论**：公开数据里**没有**"耳机音质"的独立标注；SemEval 只能当 **46 条的 sanity check**，
  **不能**作为主验证，也无法解决"评测分辨率"问题（我们测试集 treble 只有 10 条正例，同一类病）。
- **副作用（正面）**：这条侦察本身可以写进材料——"我们主动寻找外部独立验证并如实报告其不足"，
  比"声称未校准"更有说服力。

### 1.3 客观声学数据：**可用、许可宽松**（真正的差异化机会）

- [AutoEq](https://github.com/jaakkopasanen/AutoEq) 实测：**MIT 许可、16,301 stars、4.3 GB**，
  含按型号的**频响派生结果**（`results/README.md` 索引 486 KB）。
- 价值：把**主观抱怨**（"高音刺耳"）与**客观测量**（某型号 6–10 kHz 抬升）挂钩——
  这是**外部客观锚点**，不是 LLM 自证；也是竞品没有的维度。
- 边界：ASIN→型号映射困难；测量数据来源多样需逐一核许可；属 **v3 级工作（估 2–3 天）**。

## 4. 我不留情面的自我批评（对执行方自己）

1. **叙事反复透支数字**：Qwen 两轮都击中（"主动方法论跃迁""v1→v2 提升"）。根因是我倾向用**完成度口吻**讲**尚未独立校准**的结论——这是我的系统性偏向，不是偶发。
2. **"声明先于验证"是我最危险的模式**：我写"非英文评论被显式拒绝"却**从未测过那条规则本身**；这次真跑才发现**德文不被拒绝**。"写了但没验"比"写错"更隐蔽。
3. **同一错误类重复五次**（写死数字：231→238→240／包体积／审计项数）：每次都由外部指出或事后发现——说明我的"机械化"**总是慢半步**，我应当**在写下任何数字时就地加检查**。
4. **手工转录导致并行损耗**：19 项缺陷中 6 项来自红队；若有结构化回执 + 总线文件，闭环会更快（已建议 BUS 机制）。
5. **最根本的一条**：**我的产出速度 > 验证速度**，于是项目的"可信度提升"跟不上"产出量"。**产出预算必须 ≤ 审查预算**——这是我最该改的作业方式。
