# P0 预注册（品类闸门＋条件旁路＋分档）——**待决策方书面签字**

> 拟于 2026-10-03｜红队审阅后的修订版（Kimi 四条补充已并入）｜**本文件先写死判读规则，再动手**。

## 一、要改什么（出厂行为变更，故须签字）

1. **品类模型**（本地小模型，判定 耳机家族／其他音频／非音频／不明）——新增，接入报告；
2. **条件旁路**：凡品类判为「耳机家族」的评论，**绕过音频词汇闸门**，直接进音质模型评分；
3. **分档**：报告输出三档——**优先处理档／待复核档／范围外档**；
4. **来源感知封顶**：**旁路来源的条目一律封顶「待复核」档**，直到人工测出精确率才可解锁入「优先处理」——否则低质告警涌入高档，分档叙事当场崩塌。

## 二、🔴 判读规则（**先写死，防"触发数上升"自己长腿跑进材料**）

干净池 14,299 条的**期望正例数 ≈ 146**（由 X-14 基线率推出，**带 CI**）。
**触发数从 15 涨到数百，是"输入量放大"的必然结果，本身不携带任何成功信息。**

因此**预试报告必须三数同框**，并由它们算出****期望正例÷告警数之比**（>1 即触发不足）**作为唯一决策依据：

| 必报项 | 说明 |
|---|---|
| ① 品类判「耳机」子集规模 | 旁路实际放行的输入量 |
| ② 该子集上的**触发数** | 音质模型开火数 |
| ③ **期望正例区间** | 子集规模 × X-14 基线率（含 CI） |
| ⇒ ****期望正例÷告警数之比**（>1 即触发不足）** | ③ ÷ ②（若 ② < ③ 下界，则该比值 >1，**说明触发不足、可能是负收益**） |

**禁止**只报 ② 或把 ② 单独写进任何材料。

## 三、🔴 人工验证 100 条：分层含「未触发」（否则测不出召回）

**只判触发条目只能得精确率**——召回的分母（该召回而没召回的）在**未触发**条目里。

- 分层：**触发 50 条 ＋ 未触发 50 条**（均从"品类判耳机 ∧ 闸门外"子集随机抽，种子冻结）；
- **一鱼三吃**：① 精确率；② 召回率；③ **品类模型「耳机」判定的精确率**；
- ③ 之所以必需：旁路让**品类模型成为召回链的单点故障**——它把音箱判成耳机，音质模型就会在音箱评论上开火（**36% 错品类的老问题会被放大**）。故**品类模型的耳机精确率进 P0 验收线**。

## 四、🟠 挂名不测的预案（防"瓶颈定位"被跳过）

音质模型是在**富关键词文本**上训练的；旁路只给它"开火的机会"。
**若预试显示"旁路后触发寥寥"** ⇒ 瓶颈在**模型**而非路由 ⇒ 才需要拿 **P1 的全语料 LLM 标签重训音质模型**（另一世代、另一轮 R34 登记）。
**现在只挂名，不投入。**
