## 一、这一次投入要解决的三件事

| # | 需求 | 对应标签 |
|---|---|---|
| 1 | **没提关键词却是音质抱怨**（闸门外召回） | `sound_complaint` |
| 2 | **非音质差评的原因**（差评类型） | `types`（多标签，13 类） |
| 3 | **说清"模糊是怎样的模糊"** | `vague_reason`（7 类，含 NONE） |

## 二、类型表（多标签；含严格中性）

`types` = 连接/配对｜续航/充电｜做工/耐用｜佩戴/舒适｜麦克风/通话｜功能/操作｜物流/包装｜价格/性价比｜客服/售后｜描述不符/假货｜音质(听感)｜非负面/无抱怨｜其他
—— **必须含「非负面/无抱怨」**（否则类型分布被正面评论污染；照抄 `scope_classify` 的严格中性先例）。

`vague_reason` = NONE｜sound_vague｜anc_only｜functional_not_sound｜weak_praise｜not_headphone｜insufficient
—— 其中 `anc_only`（只提降噪）与 `sound_vague`（提了声音但无具体症状）对应决策方备注里的高频形态。

## 三、判读规则（**先写死**）

1. 本标注**只用于训练与分层抽样**，**不得**作为"人工校准过"的证据；
2. 本地模型的**所有数字必须与 LLM 口径并排报**，并写明：**「本地模型服务于零 API 推理，非精度最优」**（归因校验已实测：学生 0.52 vs 老师 0.68）；
3. **闸门外召回**的改善**必须由实测给出**（干净池同池对比＋分层人工样本），**不得**由召回率提升的推断代替；
4. 任何"覆盖大部分场景"的表述，必须限定为「**提到声音的评论全覆盖；其余给出差评类型与不可归因原因**」。

## 四、成本与人工

- LLM：约 **$2.8**、约 25 分钟（实测单价 $0.138/千条）；
- 人工验证：**≥100 条、每类 floor 10**（不足则只报合并口径）；**决策方约 45–75 分钟**；
- 分层：**触发 50 ＋ 未触发 50**（否则测不出召回）。
