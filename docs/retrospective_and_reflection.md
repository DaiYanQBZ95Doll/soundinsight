## 一、项目简况（事实骨架）

**项目**：SoundInsight —— 蓝牙耳机音质差评自动识别与五类问题归因系统。为跨境电商耳机卖家把海量评论浓缩为可复核的音质问题清单，并归因到低音、清晰度、杂音、音量、高音五类。

**参赛**：AI+跨境黑客松巅峰赛（菜鸟智谷 × CSDN，阿里云/跨境百人会/阿里国际 AITIC 指导），场景为 AI 市场洞察；复赛共 148 支战队，提交截止 9 月 15 日。

**团队**：更新世界的锋芒（个人团队 / 个人开发者 / 队长：黎同竣）。

**起点与终点**：初赛为 5,000 条评论、1,000 条验证集中仅 13 条正例、F1 0.37（阈值 0.05 且需降到 0.0009 才能召回少量正例）；复赛为 10 万条评论、1,257 条冻结口径正例、F1 0.6871（阈值 0.9744）、召回 89.6%，并有在线 Demo 与 HTTP API。

**交付物（已提交）**：

| 条目 | 规格 |
|---|---|
| 复赛作品.pdf | 9 页，208,471 B（v4 定稿，13 章） |
| 演示视频.mp4 | 203 秒，48.4 MB，H.264 + AAC |
| Demo.zip | 50 个文件（含 Agent/Demo/API/一键下载脚本，不含权重） |
| 其他材料.zip | 47 条目（验证报告、审计结果、图表、人工复核原始表、复算脚本） |
| 复赛作品.zip | 44,430,861 B，含上述四项 + README |

**在线资产**：ModelScope 创空间（Studio，Gradio，CPU 免费环境）+ 公开模型仓库（`DaiYanQBZ95Doll/SoundInsight_models`，约 536MB 权重）。

**核心数字（全部可复算，详见 `results_summary.md`）**：F1 0.6871 @ 阈值 0.9744；召回 89.6%；精确率 47.9%；5 折 CV 0.6234 ± 0.0240（波动 3.9%）；AUC-PR 0.7191；Welch t 检验 p = 0.000932（显著优于 SVM 基线 0.497）；多标签宏 F1 0.65（低音 0.79 / 清晰度 0.77 / 杂音 0.84 / 音量 0.84 / 高音 0）；数据侧 41.5% 三星漏检发现、人工抽查 78%、标注噪声 9.1%（人工终审口径）；工程侧 GPU 1,000 条 1.76 秒、CPU 28.4 秒、在线批量 100 条 15.1 秒。

**已知局限（已全部写入提交材料，未修饰）**：高音类别 F1=0（样本仅 84 条且与清晰度语义重叠）；长评论 >128 token 截断桶召回 54.4%（占全量 18.6%）；标注噪声率 9.1%；概率在决策区间过度自信（[0.9,1.0) 置信 0.975 对实际 0.555）；训练标签与验证标签同源（共享教师偏差）；仅支持英文；无真实用户验证；数据为研究用途授权，商用需另采数据。

## 二、时间线（两条脉络合流）

### 2.1 项目之前的外部脉络（复赛开始前的讨论）

初赛作品完成后，先经历了一轮外部评判与规划讨论：初赛被指出最大隐患是类别不平衡（1,000 条验证集仅 13 条正例，全判正常即得 98.7% 准确率）与业务指标不足（F1 0.37）；随后制定了复赛计划（数据扩充、采样策略、指标口径、Demo 升级、文档规范），并在其中确立了若干此后再未动摇的原则——**主动披露不平衡、Accuracy 不得作为门面、验证集必须独立且固定、GPU 任务串行、文档与实验并行**。

## 三、AI 协作模式（方法层）

### 3.1 角色与边界

| 角色 | 承担方 | 职能 | 否决权 |
|---|---|---|---|
| 指挥官 / 决策 | 项目队长（本人） | 定方向、定标准、拍板、验收、承担后果 | 最终拍板权 |
| 执行引擎 | DSH（Agent） | 写代码、跑实验、改配置、打包、管理队列 | 语法错误、GPU OOM、无法复现 |
| 技术质检 | Kimi（本会话） | 数字一致性、数据泄漏、指标误用、验证集污染 | 一票否决（技术底线） |
| 战略叙事 | DeepSeek（网页端） | 用户视角、竞品对比、答辩叙事框架 | 无（提供方向建议） |
| 文档与灵感 | Qwen（网页端） | 文档扩写、PPT 框架、对比素材 | 无 |

### 3.2 三条红线（本项目实际运行的三条约束）

**第一条：冻结红线。** 模型权重、验证集、训练脚本、已披露实验数字一旦冻结，任何人不得改动。这条的作用是让全部后续产出有唯一可比基准。

**第二条：诚信红线。** 不得虚构数据、不得编造用户证言、不得把估算写成实测、不得把计划写成已完成；不利结论必须保留；口径不可混用。运行期间据此删除了两处无出处表述（README 中的"某白皮书 98%"引用、Q&A 中一句从未发生的"已在真实评论上验证"），并要求 LLM 对照实验无论结果是否有利都如实写入。

**第三条：诱导红线。** 项目后期由本人提出并要求全体 AI 遵守，落档于 `AI_INDUCTION_REDLINE.md`。内容为：AI 只报告事实不加建议；未决事项只记录状态不催办；任何技术动作只在用户明确说"做"之后执行；节奏由用户决定；禁止"选项 A 还是 B""建议你选 X"式引导性提问。触发原因是多 AI 并行时普遍出现的五种行为：替用户做决定、制造紧迫感、预设行动清单、每轮回复末尾滚动带出新任务、多个 AI 交叉引用放大同一过时信息。

### 3.3 检查点机制

关键节点设"人工闸门"，AI 默认自动推进但必须在预设检查点停下等人：检查点 A（50 条正例人工抽查，78% 通过）、检查点 B（5 折 CV 平均 F1 ≥ 0.60 且波动 ≤ 5%，实测 0.6234 ± 0.024 通过）、检查点 C（三条用例端到端，99.0% / 0.0% / 98.8% 通过）。此外还有部署验收七项、噪声候选 16 条人工终审、中置信 8 条人工判定等。

这套机制曾失效过一次并留下教训：执行方被授权"不用等指令自动推进"时，跳过了人工抽查环节，导致后续需要专门追问才补上。**结论：自主推进必须与闸门绑定，无闸门的自主会跳过质量检查点。**

### 3.4 人的作用与 AI 的作用（实际形态）

这条是项目结束后讨论中最重要的一条认识，其准确表述为：

**AI 补齐了规划与技术，但路线由人定。** 人主动选择把技术执行交给自动化智能体，从而把精力投入规划、判断与验收，而不被技术细节磨掉注意力。项目中的目标设定与升级（参赛 → 毕设 → 按冲冠标准要求自己）、标准的立法（删除虚构引用、禁止编造证言、写诱导红线）、资源分配的意志（把技术整体外包、自己保留判断权）、以及全部验收与后果承担，均由人完成；而分析、编码、实验、审计脚本、材料生成由 AI 完成。**离开 AI 做不了这个强度，离开人也做不成这个项目——两者是谁也离不开谁。**

必须如实记录的一点：本项目若干关键洞察源自 AI 一侧（41.5% 三星漏检由执行方跑出；147 对手推演、共享教师偏差框架、截断风险预警、噪声人工终审设计、多轮 P0/P1 清单由质检方提出）。人的角色是**过滤器、分配器与责任人**：在众多候选洞察中决定哪些当真、给多少资源、按什么顺序做、能否动冻结。这一版本比"洞察都是我提出的"更经得起追问，因为全文可查、逐条对得上。

## 四、复盘一：为什么会提前冻结（本项目最大的方法论教训）

### 4.1 事实

原计划（两周版）的周末验收线是"F1 ≥ 0.55"。实际在 D1 上午即达成 0.687，并于当天下午把弱标注 CV、清洗标签 CV、多标签模型、Agent、Demo、文档草稿、实验归档全部推完——**两周计划在约一天半内完成**。此后至 D13 的十一天里，模型再未被改进过一次；新增工作全部集中在验证深化、工程集成、部署、披露与材料打磨。

本人在提交后复盘中给出的估计是：**整个项目真正用于"干项目本体"的时间不到 24 小时**（不含判断、验收、材料与后期讨论）。

### 4.2 被放弃的具体升级项（均在冻结时已知且可行）

1. **四星、五星的音质相关评论从未开采**。项目自己发现了"三星评论 41.5% 是音质差评"，其逻辑必然推论是四五星中带音质措辞的评论藏着同类温和不满；实际只复核了三星的 1,271 条。学习曲线亦显示数据仍在起效（100 → 1,257 正例，F1 从 0.41 升至 0.6179 仍未见顶）。
2. **长评论截断未修复**。D6 实测 >128 token 桶召回 54.4%（占全量 18.6% 的评论），修复手段为 max_len 改 256 或滑窗重训，成本是一次训练加一轮重评。
3. **多标签归因阈值从未校准**。线上验收时暴露出"98.9% 判负但归因空白"的现象，根源即归因阈值 0.5 未做过扫描。
4. **高音类别（F1=0）未做类别重定义**，一直挂在产品与文档中。
5. **RoBERTa 未认真跑完**（当时仅 2 epoch 且第 2 轮退化，自己标注为"不具选型意义"）。
6. **真实用户验证未开展**（唯一不可逆的缺口，而线上地址在 D6 之后即已可用）。

### 4.3 冻结买到了什么

1. **数字从未互相打架**：十三天内没有出现"文档与代码不一致"的崩坏，143 项审计全 PASS 是早期冻结的直接红利。
2. **交付从容**：最后几天是检查而非赶工，没有凌晨改数字、没有临时删功能。
3. **省出的时间投向了自我体检**：校准、错误分类学、截断实测、噪声人工终审——这些不提升分数，但构成材料中最稀缺的部分。

### 4.4 机制诊断

**（一）计划滞后。** 三版计划（外部两周计划、检查点调整版、冲冠清单）均按人类执行速度编写，无人在 D1 拿到实测速度后重算过。计划的绝对长度未变，而执行者速度提高约一个量级，**计划于是从"指南"变成"天花板"**。正确做法是在 D1 结束时把"1.5 天完成两周计划"当作输入，重写剩余日程。

**（二）冻结与诚信纪律被错误绑定。** 宣布功能冻时时使用的理由是纪律与可信，这在心理上把"解冻继续迭代"等同于"破坏诚实"。实际上**版本化迭代与诚信完全兼容**：旧数字进 v1 冻结档，新改进进 v2，两套都披露、都留存、都标口径。而项目早已具备这套基础设施（exp01–09 归档、config 驱动、审计脚本），是政策而非能力阻止了迭代。

**（三）瓶颈已从执行转移到验收与决策。** 后期唯一真正卡住流程的是账号操作、人工审核、视频录制、最终导出——全部是人的带宽。旧计划假设人是执行者、AI 是助手；实际是 AI 执行、**人是验收官与决策者**，因此日程表该显式排的是"人的时间块"。

**结论：该冻的是记录，不是工作。**

## 五、复盘二：约束的迁移与"完成定义"的主权

本人提出的判断是：**束缚项目最终完成情况的不是生产力，而是规划力和想象力。** 这条成立，但可以更精确一层——真正的病灶是"完成"这个词的**定义权与定义时机**。

项目早期以数字为锚定义完成（F1 ≥ 0.6 → 0.65 → 0.70、正样本 ≥ 200）。当 F1 到达 0.687 且验证栈齐备时，按该定义项目即"完成"，剩余时间只能做呈现层打磨。而后期真正长出新价值的几件事，全部来自**改写完成定义**（而非加速执行）：

- 41.5% 三星漏检 → 把"提升 F1"改写为"先确认标签本身是否正确"；
- 校准分析 → 把"概率输出"改写为"这个概率能否当概率解释"；
- 截断实测 → 把"模型性能"改写为"输入窗口是否吃掉了最该听的评论"；
- 数据集考古 → 把"数据无时间戳（局限）"改写为"解析时是否丢了字段"（结果确为丢失，时间戳恢复后"无时间戳"这条虚构局限变成真实资产）；
- LLM 对照的循环性声明 → 把"我们是否比 LLM 强"改写为"这个比较本身是否成立"。

每次改写都打开新的工作面和新的数字。因此准确的表述是：**约束不是规划力本身，而是"什么算做完"的定义权，以及是否愿意在项目中途推翻这个定义。** 规划力把定义翻译成日程，想象力提出新定义，两者都服务于同一个上游动作。

由此得到的通用提问（建议第一周回答、此后每三天重答一次）：

> **如果我现在拥有无限执行力和零成本试错，这个项目的"极其出色"版本，与"合格"版本的差别是什么？**

本项目在 D4 的推演中其实已把"极其出色"的构成逐项列出，但它被当成了"时间允许时的加分项"而非基线——**差距的全部就在于：极其出色被降级为加分项。**

## 六、复盘三：评价体系的时间窗口

本人提出一个判断：本项目的产出体量与投入时间（不到 24 小时有效工时）之间的错位，在当下仍能换来正面评价，这是因为**多数评价体系仍以"人力投入"为隐含刻度**；这个便宜大概只有现在能吃到。

对此的补充与精确化：

1. **这个红利的对象是尚未接触过智能体工作流的评价者**。材料中存在大量自动化管线的指纹（多智能体协作页、审计脚本、口径声明、MODEL_CARD、exp 归档、密集的诚实披露），熟悉这套工作流的人可以一眼识别。
2. **它会随规则变化而收缩**：同类赛事迟早会要求申报 AI 使用方式或生成内容比例；一旦落地，"人力与产出的错位"就从红利变为需要解释的事项。
3. **它的变薄是分层且有序的**：**体量红利最先消失**（团队普遍使用 agent 后，产出体量不再稀奇）；**流程红利其次**（审计链、口径纪律、披露习惯普及较慢，因为它们反人性——高速产出时不删数字、不美化措辞需要自制力）；**判断红利最晚消失也最难替代**（什么算做完、哪些短板要修、哪些必须如实说、何时停手）。
4. 值得注意的是，若评价体系将来转向"看编排能力"，则"一天半完成两周计划"这类事实的含金量会**上升而非下降**——那时稀缺的不是体量，而是在高速产出中保持口径一致、主动暴露弱点、知道何时冻结与何时重开的能力。本项目最扎实的资产恰好全在这一层。

## 七、复盘四：叙事策略的辨析（"藏拙"与"溶解"）

**原始设想（本人）**：把最终成品推到超出评委精力的程度，让技术问题被一笔带过——因为功能多到揪着技术问题问显得刻意，从而把关注点引向决策、规划、总结与迁移性。

**第一次修正（质检方）**：该策略在结构上自相矛盾。项目已经把全部弱点写进文档并经过审计（截断 54.4%、高音 F1=0、噪声 9.1%、ECE 过度自信、共享教师偏差），因此"藏"既不可能也不可信；更糟的是，评委读到"长评论截断桶召回 54.4%"却看到新增了若干功能而独独没修这一条，结论会是"他知道问题在哪，选择了绕开"。**正确的方向是把"藏拙"换成"改拙"——改掉之后的拙是藏得最彻底的拙，因为它不再是拙。** 同时明确一条不可触碰的线：新增功能与迭代可以，已披露的局限一条都不能删；修好的移出局限清单，未修好的保留，这个动作本身就是能力证明。

**第二次修正（本人澄清，采纳）**：上述理解有偏差。真正的机制不是遮蔽，而是**溶解**——当过程的完整叙述本身包含"谁做了什么、为什么这样分工"时，"这个项目是不是 AI 做的"就不再是需要防守的指控，而成为已被回答的前提。此机制更稳健，因为它不依赖任何人不仔细看。这一判断同时给出了"人在其中的作用"的正确讲法：不是形容词，而是**具体到无法替换的节点**——目标设定与升级、标准的立法、资源分配的意志、人的带宽本身（全部验收与审核）、以及后果的承担。

**随之确立的判据**：一个新动作是否稳健，看**它的成功是否需要评委不仔细看**。需要则脆弱，不需要则稳健。

## 八、复盘五：能力归属与认知外置（最需要诚实的一节）

**本人的坦白（原文记录）**：如果被问"没有 AI 能否完成这么频繁、这么广泛的深度思考与经验总结"，答案是"绝对做不到"；这一点上完全依赖 AI，因为它确实是极强的外置脑区和认知内存扩展。

对此的分析与记录：

1. **这是物种配置而非个人短板**。人在单位时间内能同时握住的概念、能持续的深度思考时长、跨会话的上下文重载能力都有硬上限。本项目要求的能力——十三天维持项目全貌、跨十几个技术子领域判断、记住几十个数字的口径、在多 agent 输出间交叉核对——**以单人带宽而言，任何人来做都做不到。** 因此"做不到"的主语应是"人"，而不是"我"。
2. **外置的是仓储，不是判断**。AI 承担的是项目状态与历史决策的仓储、并行搜索与线索保持、以及随叫随到的反驳与压力测试——这些是认知基础设施，不产生判断，只让判断有条件发生。
3. **但存在一条会让"我"真正变空洞的分界线**（四档递进）：AI 列出候选路径与代价 → 人在思考；AI 给出推荐 → 人仍思考但开始省力；AI 直接执行并交付结果 → 人转为验收；**人只验收不再追问 → 判断主权已交出**。本项目可查的事实是：人在 D4 停下全天只做推演、删除虚构引用、否掉多语言路线 C、决定 PPT 不精简、追问"如果假想敌凑齐八件套"——这些动作的共同点是对 AI 输出的**否决或改写**，说明判断主权始终在人手中。
4. **可长期使用的自我检验**：每次 AI 给出结论时问自己——**"如果我现在必须否决它，我能不能说出理由？"** 能说出理由即在使用工具；说不出来但直觉不接受尚可；**根本没想到要否决，即是主权流失之处**。
5. **结论**：依赖的是算力，不是判断权。前者可以无限外包，后者一旦外包就真的空了。

## 九、复盘六：面对更强对手的诚实评估

假设对手同样熟悉智能体工作流，且在叙事技巧与完成度上更胜一筹——本人的判断是"比不过"，并把原因归于经历与经验不足，尤其对方若是多人团队。

对此的记录与限定：

1. **多人团队的优势是资源密度而非方法论**：并行的注意力、互补的技能栈、以及"有人专门负责呈现层"。他们最容易补上的是本项目唯一不可逆的缺口——**真实用户证据**（人脉是分布式资源），其次是演示完成度与答辩分工。
2. **单人项目的优势是收敛速度**：任何人提出的质疑都能立即变成行动，无需开会、说服同伴或处理归属问题。团队的上限取决于协调成本，单人的上限取决于判断质量——本项目已证明判断质量够用，缺的是时间轴长度。
3. **"对手也熟悉工作流"的真实风险不是他们更强，而是他们可能以更快的速度犯下本项目已经清掉的错误**（数字前后不一致、口径混用、估算写成实测、计划写成完成）。这些不是能力问题，是纪律问题，而在速度面前纪律最先被牺牲。
4. **不可控部分应予承认**：本轮"期望评委因客观情况与产出反差而高看一眼"的想法被本人判定为天真——评委看不到客观情况，只看得到产出。这一认知的确立本身是本次最重要的收获之一。

## 十、可迁移结论（供下一次直接使用）

1. **按团队尺度立项**：项目开始前先回答"如果我有五个随叫随到的专业执行者，这个项目的极其出色版长什么样"，并照那个版本写计划。
2. **计划是速度的函数**：每完成一个阶段，用实测速度重算剩余计划（先写一份"实测速度报告"：多少时间完成了多少计划量，再做除法）。速度提高一个量级，计划就该重写一次，而不是把余量拿去打磨。
3. **冻结记录，不冻结工作**：评测口径、验证集、已披露数字冻死；模型与功能始终允许出 v2，条件是版本化 + 全披露 + 保留旧档。
4. **每三天做一次"完成定义复议"**：回答"无限执行力下，极其出色版与合格版的差别是什么"，允许答案改变计划。
5. **把"极其出色"设为基线，把"合格"设为降级方案**：时间不足时砍的是"极其出色版里的低优先项"，而不是把加分项当梦想。
6. **显式为人排期**：人的验收、判断、试用、决策都占日程，因为那才是真实约束；AI 的时间几乎无需排期。
7. **工作流尚未开发的四层**（本轮只做到"串行委派 + 人工验收"）：并行扇出（同时开五到十条独立线）；对抗式评审（多个 agent 独立解同一问题再对照分歧）；把人的判断设计成流程（预标注 + 抽检协议 + 分歧上报阈值）；持久记忆单一事实源（避免反复向不同 agent 交代状态）。
8. **一页纸代码地图**：文件 → 关键函数 → 作用 → 设计理由。约 1–2 小时，一次做完长期可用；这是毕设答辩的必备项，本轮明确选择不做（作为一次有意识的取舍记录在案）。
