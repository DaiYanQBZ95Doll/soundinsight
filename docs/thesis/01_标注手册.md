# 标注手册（Annotation Manual）v1.0 · 冻结版

> **任务**：判定一条电商评论是否**在抱怨目标品类产品的音质／听感**，并为确认的抱怨给出问题类别。
> **适用范围**：Amazon Reviews 2023（Electronics，英文）中的**耳机家族**（headphone/earbud/headset）与**音箱家族**（speaker/soundbar/other_audio）评论。
> **冻结**：v1.0 冻结于 2026-10-14；此后任何改动须升版并记录变更点（§10）。
> ⚠️ **诚实披露**：本手册为**首轮判读之后**整理（依据首轮 292 条判定与其中 131 条理由备注）。首轮判读时**尚无书面手册**——此为本研究的已知局限，须在论文中披露（见 §6）。

---

## 1. 编码定义

| 编码 | 含义 | 判据 |
|---|---|---|
| **1** | **是**——该评论在抱怨**目标品类产品**的**音质／听感** | 有明确的负面态度，且负面对象是声音表现（音质、听感、音色、低频/高频、清晰度、杂音、音量等） |
| **0** | **不是** | ① 产品非目标品类；② 未涉及声音；③ 涉及声音但**不是抱怨**（褒奖、中性描述、对比举例）；④ 抱怨的是与声音无关的问题（连接、延迟、续航、佩戴、物流、价格） |
| **2** | **无法判断** | 信息不足或语义模糊到无法确定是褒是贬；**不得用于回避判断**（§7） |

**目标品类判定优先于一切**：若产品明显不是目标品类（如平板电脑、功放、音频太阳镜），直接判 **0**，不再考虑声音。

---

## 2. 判读顺序（四步，按序执行）

1. **产品是什么？** 是否属于目标品类（耳机家族／音箱家族）→ 否 → **0**，结束；
2. **是否提到声音？** 是否出现对声音表现的描述 → 否 → **0**，结束；
3. **是不是抱怨？** 负面态度是否指向声音 → 否（褒奖／中性／抱怨其它问题）→ **0**，结束；
4. **（仅编码 1 时）归因**：低音／清晰度／杂音／音量／高音；**无法归入五类**（如降噪、风噪、通透模式）→ 标"类目缺口"；**未指明具体方面**（只说"音质差"）→ 标"未指明"。

---

## 3. 规则清单（R1–R9）

| # | 情形 | 判定 | 依据（首轮锚例） |
|---|---|---|---|
| **R1** | 功能故障**提及**声音（断连、单侧无声、线材、配对失败） | **0** | "这个是抱怨连接问题" "抱怨的其实不是音质问题，而是延迟问题" |
| **R2** | 对声音的**褒奖** | **0** | "这个其实不是抱怨而是赞扬" "并不是抱怨，而是举例对比，实际上是赞扬" |
| **R3** | 中性／描述性提及声音（如"它有 40mm 单元"） | **0** | "这个其实是没有问题的" |
| **R4** | **降噪／风噪／通透模式**抱怨 | **1**（属听感）＋ 归因标"类目缺口" | 首轮将此类计入声音抱怨，但五类中无对应项 |
| **R5** | 非目标品类（平板／功放／音频太阳镜） | **0** | 首轮"1 条为非耳机产品（音频太阳镜）"被计为误报 |
| **R6** | 抱怨主体是音质，同时夹杂佩戴／续航等 | **1** | "有杂音，同时佩戴体验不舒适，但本身的音质反而没什么大问题，是一个弱相关" |
| **R7** | 明确说"音质差／声音糟"，但**未指明**具体方面 | **1** ＋ 归因标"未指明" | "提了音质不行但没说具体是哪方面，但也确实是音质差评" |
| **R8** | 语义**模糊到无法判断褒贬**（如"感觉不太好""不可接受"但语境不明） | **2** | "先说音质不错，但又说感觉不太好，不确定" |
| **R9** | 抱怨**可能**来自配件或外接设备（如车载扬声器）而非本品 | **2**（除非能确定指向本品） | "评论者提到了可能是货车扬声器的问题，不确定，但确实是音质反馈" |

### 规则说明（关键消歧）

- **R7 与 R8 的分界**：**态度明确**（明确说差／糟／失望）→ **1**；**态度不明**（可能是褒可能是贬）→ **2**。
  ⚠️ 首轮在此边界上出现过**不一致**（同属"提到声音为负面但未指明方面"，一条判 1、一条判 2）。本手册据此明确规则；重测将按本规则执行——这意味着**重测一致性会略高于首轮的真实稳定性**，论文中须如实说明（§6）。
- **不得因为"归因困难"而降级为 0 或 2**：归因是第 4 步的事，前 3 步已判 1 的条目不应因归因不了而改判。

## 4. 锚例（来自首轮真实判定，供判读时对照）

**判 1 的锚例**
- "完全没有低音" → 1（归因：低音）
- "清晰度问题，确实跟音质有关" → 1（归因：清晰度）
- "杂音问题，除此以外还有断续的问题" → 1（归因：杂音；断续不影响判定）
- "中等偏高的音量下失真、有杂音，并且有断连的问题" → 1（音质抱怨为主，断连为辅）

**判 0 的锚例**
- "这个是抱怨连接问题" → 0（R1）
- "抱怨的其实不是音质问题，而是延迟问题" → 0（R1）
- "这个其实不是抱怨而是赞扬" → 0（R2）
- "这个说的其实不是音质问题" → 0（R1/R3）

**判 2 的锚例**
- "先说音质不错，但又说感觉不太好，不确定" → 2（R8）
- "有提到声音很糟糕（但是没具体说明是哪个音质的具体相关项）" → 首轮判 2；**按本手册 R7 应为 1**（见上方消歧说明）
- "评论者提到了可能是货车扬声器的问题，不确定，但确实是音质反馈" → 2（R9）

## 5. 判读操作规范

1. **只看单条评论**，不跨条目比较，不看模型输出；
2. **不看模型分数、不看臂归属**（触发/未触发）——若不可避免，须在论文中标注为单盲；
3. 每条判定耗时 **10–20 秒**；不确定时**先按四步顺序**走一遍，仍不确定才用 2；
4. **备注可选**，但出现以下情形时**建议写**：犹豫、与判据冲突、类目缺口、发现新情形（后者将成为手册升版的依据）；
5. 记录格式：`**判定（决策方填）**：\`_1__\`<可选理由>`。

---

## 6. 已知局限（须写入论文）

1. **首轮无书面手册**：判据为隐含经验，手册为事后整理；
2. **单标注者**：无法报告标注者间一致性（κ）；以**重测一致性**（§8）与**人机一致性**（§9）替代；
3. **边界不一致**：R7/R8 边界在首轮存在不一致（已在 §3 消歧，且会抬高重测一致性）；
4. **类目缺口**：降噪／风噪等听感问题在五类归因中无对应项（首轮以"类目缺口"记账）。

---

## 7. "无法判断"（2）的使用约束

- **仅在信息不足或语义模糊**时使用；
- **上限建议 ≤5%**（首轮 292 条中为 5 条，≈1.7%）；若某批次超过 10%，视为判据不清，应停止并升版手册；
- **禁止**因"懒得归因""模型可能想判 1"而使用 2。

---

## 8. 重测协议（intra-rater reliability）

| 项 | 规定 |
|---|---|
| 抽样 | 从已判池按原判定分层抽 100 条（种子冻结，见 `v2/retest_ids.json`） |
| 间隔 | **≥7 天**（首批判读 2026-10-05/06/07，重测自 2026-10-14 起可执行） |
| 盲性 | 卡片**不显示**原判定、模型分数、来源与臂归属；**禁止翻看旧卡** |
| 指标 | 一致率（agreement）＋ **Cohen's κ**（自身前后）＋ 按域（耳机/音箱）与按原判定分层的分解 |
| 解释 | κ ≥ 0.8 优；0.6–0.8 良；0.4–0.6 中；< 0.4 判据不稳（须升版手册并重测） |

---

## 9. 人机一致性（human–LLM agreement）

- 对照者：训练所用 LLM 银标（版本与 prompt 已冻结留档）；
- 指标：一致率 ＋ κ；不一致条目**分类记账**：模型误报／模型漏报／判据差异（人更严）／类目缺口／非目标品类；
- 用途：① 量化"LLM 银标 vs 人工口径"的性能差（本研究的核心发现）；② 在只有一名人工标注者时提供第二参照。
