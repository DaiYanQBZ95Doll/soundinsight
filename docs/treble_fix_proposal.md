# 高音归因修复方案（treble_fix_proposal.md）

> 前置：失效机制已定位，见 `docs/treble_failure_analysis.md`（零触发：最大概率 0.3332 < 阈值 0.5）。
> 本文件给出**三档修复方案**，含实测收益、代价、以及"哪些东西仍然冻结"的边界。
> 触发条件：若入围决赛（用户决定）。当前仍处冻结状态，**未实施任何修复**。

## 一、方案 A：逐类阈值（不动权重，成本最低）

**做法**：多标签判定从"统一 0.5"改为逐类阈值，阈值作为配置项（`config.json`）而非硬编码。

**实测收益**（`tune_per_class_threshold.py`，验证划分 252 条）：

| 类别 | 统一 0.5 的 F1 | 最优阈值 | 逐类阈值 F1 |
|---|---|---|---|
| 低音 | 0.7945 | 0.20 | **0.8642** |
| 清晰度 | 0.7714 | 0.25 | **0.8313** |
| 杂音 | 0.8392 | 0.35 | 0.8400 |
| 音量 | 0.8356 | 0.60 | **0.8652** |
| **高音** | **0.0000** | **0.20** | **0.5161** |
| **宏 F1** | **0.6481** | — | **0.7834（+0.135）** |

- 需要改动：`config.json`（新增 `issue_thresholds`）、`predict_core.py` 与 `soundinsight_agent.py` 的判定处（读配置，缺省回退 0.5）。
- 不需要改动：模型权重、`val_v2.csv`、训练脚本——**不触碰任何冻结物**。
- 代价：约 1 小时（含改代码、回归测试、写文档）。
- 风险与披露要求：
  1. 阈值是在**同一验证划分**上网格搜索得到的 → 指标偏乐观；对外引用前必须改用**交叉验证或独立调参划分**重选阈值（否则属"在同一集合上调参并报数"）。
  2. 高音 FP 会上升（验证划分 8 TP / 10 FP），要在报告里写清"高音类误报增加"。
  3. `results_summary.md` 的 **0.6481（统一阈值）保持不动**，逐类阈值结果作为**新增指标行**单独记录。

## 二、方案 B：类别加权重训（需解冻，收益更实）

**做法**：多标签训练改用带 `pos_weight` 的 BCE（按各类负正比设定，高音权重最大），并改用**多标签分层**划分（iterative stratification，替代当前 `stratify=Y.argmax(axis=1)`）。

- 预期：高音召回提升，且大概率不必把阈值压到 0.20；其他四类基本不变或微升。
- 代价：1-3 小时（改训练脚本 + GPU 重训 ~5 分钟 + 评估 + 文档）。
- 必须遵守的边界：
  1. **不覆盖冻结模型**：新模型存到新目录（如 `multi_label_model_v2/`），旧模型与其指标原样保留；
  2. 用**独立划分**评估，并同时报告统一阈值与逐类阈值两套结果；
  3. 高音标签仍用 84 条还是改用补捞后的 124 条，需明确并披露（当前冻结模型是 84 版本）。
- 提醒：二分类上的消融 B 已证明 class_weight 会"过补偿"（精确率崩到 35.5%），多标签侧的权重需要重新调，不能照搬。

## 三、方案 C：标签重定义 + 重训（治本，成本最高）

**做法**：先治标签，再重训。
- 依据（实测）：高音正例 84 条中 **40.5% 同时标了清晰度**；含高音关键词的 206 条评论里 **129 条（62.6%）漏标高音**。
- 两条可选路线：
  - **合并**：把"刺耳/尖利"明确归入"清晰度"，取消独立高音类 → 宏 F1 直接受惠（剔除高音后四类宏 F1 = 0.8102）。代价是失去一个细分维度。
  - **细化高音定义**：明确"高音过亮/刺耳/齿音"的判据，对 206 条关键词评论做**重标 + 人工抽查**，再重训。
- 代价：0.5-1 天（重标需 LLM 复核 + 人工抽查；本轮已删除用户反馈环节，人工部分需用户本人参与）。
- 收益上限最高，且能顺带解决"清晰度被高音污染"的问题。

## 四、三档对比

| | A 逐类阈值 | B 加权重训 | C 标签重定义+重训 |
|---|---|---|---|
| 是否动权重 | 否 | 是（新目录） | 是（新目录） |
| 是否触碰冻结物 | 否 | 需解冻多标签训练 | 需解冻 + 重标 |
| 实测/预期宏 F1 | **0.7834（实测）** | 预计 0.78-0.82 | 0.80+（取决于标签质量） |
| 高音 F1 | **0.5161（实测）** | 预计 0.55-0.70 | 取决于合并/细化路线 |
| 耗时 | ~1 小时 | 1-3 小时 | 0.5-1 天 |
| 主要风险 | 同集调参偏乐观、FP 上升 | 权重过补偿；新旧模型并存需讲清 | 重标引入新的标注噪声 |

## 五、建议顺序（供决策，非强制）

1. 先做 **A**（当天可完成，且不改模型，风险最低）——先拿到"高音不再是 0"的可用产品行为；
2. 若时间允许，再做 **B**（让高音不必靠 0.20 这种激进阈值撑住）；
3. **C** 视决赛时间与人力决定；若做合并路线，需同步更新文档、PPT 与 Q&A 中"五类归因"的表述（改为四类或"四类 + 刺耳并入清晰度"）。
