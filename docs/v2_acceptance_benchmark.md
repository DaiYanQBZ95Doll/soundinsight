## 一、为什么不能直接搬主流的 ABSA/ACSA 数字

检索到的最亮眼公开数字来自情感分析基准：ACSA（aspect-category sentiment analysis）上 BERT 分类模型可达 **F1 90.89**（见 [Solving Aspect Category Sentiment Analysis as a Text Generation Task](https://ar5iv.labs.arxiv.org/html/2110.07310)）。但该数字与本项目任务存在结构性差异，不可直接对照：

| 差异 | 主流 ABSA / ACSA | 本项目 |
|---|---|---|
| 方面（aspect）是否已知 | 给定方面后判极性 | 需从全量评论中**自行判定**是否含音质抱怨 |
| 类别分布 | 各方面内正负相对均衡 | 正例 **1.26%** |
| 任务结构 | 多分类 / 序列标注 / 四元组抽取 | 极端不平衡二分类 |
| 阈值 | 多使用默认阈值或未声明 | 本项目使用验证集扫描的最优阈值 |

**结论**：直接比较会重复项目内部早已标记的口径风险。可用参照必须是三层：可验算的自有锚点、同构任务族区间、教师—学生落差。

## 二、第一层参照：本项目自带的可验算锚点（最硬）

| 锚点 | 数值（**含阈值档**） | 关系 |
|---|---|---|
| 正例占比 p | 251 / 20,000 = **1.26%** | — |
| 全判正常（dummy majority） | **F1@0.5 = 0.0000** | 平凡预测器的真实成绩 |
| 平凡预测器上界（阈值扫至 ≤0，等价全判正） | **F1 = 0.0248** | 精确等于 2p/(1+p) = 0.0249 |
| 传统方法天花板（TF-IDF + 线性 SVM，清洗标签 5 折） | **调优 F1 = 0.497** | 最强非深度基线 |
| 逻辑回归 | 调优 F1 = 0.410 | 参照下界 |
| 无同源红利的 LLM 上限（qwen3.7-plus 零样本，同子集） | F1 = **0.9149** | 见 `llm_baseline.md` §2b |
| 含同源红利的 LLM 上限（deepseek-chat 零样本） | F1 = 0.9400 | **不得**作为绝对上限引用 |
| v1 主指标 | **F1@调优(0.9744) = 0.6871**；P 66.3% / R 71.3% | 相对平凡上界 **27.7×**，相对 SVM **+38.3%** |
| v1 的 0.5 档 | **F1@0.5 = 0.6241**；P 47.9% / R 89.6% | 高召回档 |
| v1 的 PR-AUC | **0.7191** | 相对随机水平 0.0126 为 **57×** |
| v1 的 5 折 CV | 调优 F1 = 0.6234 ± 0.0240（波动 3.9%） | 含选择偏差，见 §四 |

### 2.1 dummy 基线订正说明（须写入 v2 勘误）

`results_summary.md` 原文：`dummy(全判正常): acc=0.9874 | f1@0.5=0.0000 | f1_best=0.0248`。

- **全判正常的 F1@0.5 是 0.0000**，与 `DummyClassifier(strategy="most_frequent")` 的行为一致（正例仅 1.26% 时它恒预测负）；
- **0.0248 是阈值扫至 ≤0 后的取值，此时等价于"全判正"**，其解析解即 2p/(1+p)。

**影响面**：`competition_v4.md` §7.1 写"随机基线 F1=0.025"、§7.4 表列"全判正常（dummy）0.025"，README 与 AI_HANDOFF 沿用同一说法。"相对平凡上界 27.7×"这一卖点本身站得住（用 0.0248 作分母比用 0 更保守），**但标签错误**——评委只须追问"全判正常怎么会有 0.025"即需当场解释。

**处理**：v1 已冻结不改；v2 以勘误方式写清——"全判正常 F1@0.5 = 0.0000；dummy 取阈值扫描最优值（等价全判差评）= 0.0248，本项目以其为平凡预测器上界"。**数字一个不动，只改标签。**

## 三、第二层参照：同构任务族（稀有事件检测）区间

同构任务族为**从用户生成文本中检测稀有事件**，技术特征与本项目一致：类别不平衡处理、逐类阈值优化、PR 曲线优先（见 [SMM4H-HeaRD 2026 多种子集成 + Focal Loss + 分语言阈值优化](https://aclanthology.org/2026.smm4h-1.2.pdf)；不平衡数据集研究覆盖 [0.126 起偏低的正例占比](https://www.mdpi.com/2227-7390/14/17/3194/pdf)）。

| 任务族 | 一般区间（**需核对原文，勿作既定值引用**） | 可比性 |
|---|---|---|
| 药物不良反应 / 不良事件检测（社媒短文本） | 约 0.5 – 0.8 | **高** |
| 评论中的缺陷 / 质量投诉挖掘 | 约 0.5 – 0.75 | **最高** |
| 多标签毒性内容中的稀有类别 | 约 0.4 – 0.7 | 中高 |
| ABSA / ACSA 极性分类 | 0.75 – 0.90 | **低**（不可直接比） |

**读法**：v1 的 0.6871（调优口径）落在该族**中上位**；0.75 以上接近该族上四分位。

## 四、阈值选择偏差与评估协议（本版新增，优先级最高）

### 4.1 问题

v1 在验证集上网格搜索最优阈值，再在**同一验证集**上报告指标：

- `distilbert_cv.py` 第 90 行：`f1b, _ = best_threshold_f1(yva, probs)`——**阈值在验证折上选取、指标也在该折上报告**；
- 最终模型的最优阈值 0.9744 亦在 val_v2 上选出，0.6871 同样报在 val_v2 上。

**含义**：v1 的 0.6871 与 0.6234 ± 0.0240 均含**阈值选择偏差（乐观偏置）**，属"在同一集合上调参并报数"。**该偏差 v1 从未显式披露**——此为本轮审查新发现，且同样适用于逐类阈值方案（`docs/treble_fix_proposal.md` §一 风险 1 已自行标注"指标偏乐观"）。

### 4.2 协议（v2 必须遵守）

1. **val_v3 一分为二**：`val_v3_tune`（选阈值、选早停）与 `val_v3_test`（只报告，**不参与任何调参**），划分固定种子并记录；
2. **或**交叉拟合：K 折内每折在 K−1 折调阈值、在留出折评估，汇总报告；
3. **文档口径**：对外指标须注明"阈值在独立调参划分上选取"；
4. **v1 数字**：不改数字，但须在 v2 文档中显式声明其调参方式与由此产生的乐观偏置（如实披露，不属作废）；
5. **闸门第 (1) 条主指标一律取 `val_v3_test`**。

**这一条比"目标值取 0.72 还是 0.75"更重要**——它决定 0.72 是真是假。

## 五、四档门槛（全部绑定阈值档 + 独立评估划分）

| 档 | 判据（**阈值档已标注**） | v1 位置 |
|---|---|---|
| **及格（可用）** | 调优口径：F1 ≥ 0.66 且召回 ≥ 68%；或 0.5 口径：F1 ≥ 0.60 且召回 ≥ 85%；显著优于 SVM（p < 0.05） | 两档均满足 |
| **良好（扎实）** | 调优口径：F1 ≥ 0.68；CV 波动 ≤ 5%；验证栈完整（基线 / 消融 / 显著性 / PR / 学习曲线 / 校准 / 错误分类 / 长度分桶） | 边缘达成（0.6871） |
| **优秀（出色）** | 调优口径：F1 ≥ **0.72**（≈ 教师上限 79%、SVM +45%）**或** PR-AUC ≥ **0.75** **或** 相对平凡上界 ≥ **30×**；主指标取独立划分 | 差 **0.033** |
| **极其出色** | 调优口径 F1 ≥ **0.75** **且** 截断桶召回 ≥ **70%** **且** ≥1 条完整闭环（发现→量化→修复→前后对比）**且** 已披露短板逐条结清 | 需实质迭代 |

**口径提示**：初版"及格"行把"F1 ≥ 0.60 与召回 ≥ 80%"并列，隐含两个不同阈值——v1 只在 0.5 档同时满足，在调优档为 F1 0.6871 / R 71.3%。本版已按档分列。

### 已在项目内、可直接进闸门（零成本）

1. **校准基准**：整体 ECE **0.0122** 看似优秀，实因 97% 样本落在 [0,0.1) 稀释所致；决策区间显著过度自信（[0.9,1.0) 置信 0.975 对实际 0.555）。**闸门应改用"决策区间（≥0.5）各箱偏差绝对值 ≤ 0.15"**；若引入校准器（温度缩放 / Platt），**必须在 `val_v3_tune` 上拟合、在 `val_v3_test` 上报告**，否则构成新泄漏。
2. **稳定性基准**：CV 折间波动 ≤ 5%（v1 为 3.9%）；可补**多阈值稳定性**（不同种子下最优阈值的方差），v1 未测。
3. **成本基准**：GPU 1,000 条 **1.76 s** / CPU 28.4 s / 在线批量 100 条 15.1–20.1 s。LLM 侧数字引自 `llm_baseline.md` §2（deepseek-chat，输入 $0.27/M、输出 $1.10/M，按实测比例约 82%/18% 估算 3,000 次判定约 **$0.1 ≈ ¥0.7**）；**须补官方价目来源链接与抓取日期**，否则只能作"估算"引用。v2 若换更大基座，须同步给出新吞吐与显存实测，否则"本地零成本"出现空白。

### 需要新实验、成本低（建议纳入 v2）

4. **基座对比矩阵**：DistilBERT（现）vs BERT-base vs RoBERTa-base vs DeBERTa-v3-small，同配置对照；分钟级，超时缩为两个基座。
5. **数据效率对照**：把既有学习曲线（1,006→1,257 正例使 F1@0.5 由 0.5666 升至 0.6179，未见顶）重述为"达到 F1 0.65 所需标注量"单值，用于回答"数据够不够"。
6. **长文本方案对比**：max_len 256 vs 512 vs 滑窗 vs 分段聚合，在 >128 token 桶上的召回对照，构成截断修复的完整闭环素材（叙事价值最高）。
7. **非音频 / 非耳机子集的误报率（替换初版"跨品类零样本"）**：
   - **初版成本估算不成立**：仓库仅有 Electronics 品类数据，美妆/厨房/个护需另行下载（每品类数 GB）；且**无标签无法计算 F1**，只能定性判断。"成本仅推理"作废。

   - 若确需跨品类：须把数据获取计入成本，并按"人工/LLM 判 N 条"的定性旁证呈现，**不得表述为"已转做多品类"**。

## 九、工具链与存档规范（防半代污染）

1. **代际标签写法**：文档内实验数字须带 `[v1]`（复赛已提交口径）或 `[v2]`（决赛口径），首次出现处附说明。
2. **审计代际感知**：`check_doc_numbers.py` 改为"每代一套必需项 + 当前代开关"；同一文档内出现两代数字而无口径标注 → FAIL。将"阈值配对检查"扩展到全部 F1/召回/精确率（本文件初版即在"及格"行犯过该错）。
3. **模板合规检查（决赛版）**：九节齐备 + 编号唯一 + 在线链接表填写 + 团队信息 + **5.2 百炼栏按 §6.0 的既成事实填写**。
4. **v2 可核验产物**：权重不入库，但须入库模型文件 SHA256、`threshold.json`、训练命令、评估原始输出，并登记于 v2 版 MODEL_CARD。
5. **哈希与清单同步**：采纳 v2 时同步更新 `hashes.txt`、`manifest.json` 与内容类哈希；**不得覆盖已提交的复赛包**（红线 9）。
6. **生成顺序**：`check_doc_numbers.py` → `scan_repo_hygiene.py` → md_to_pdf/docx → `build_submission.py` → `pack_final.py` → `make_ai_handoff.py`。

## 十、优先级意见（供决策，非强制）

| 序 | 项 | 依据 |
|---|---|---|
| ① | **长文本截断修复** | 可判定、可讲闭环、答辩最易被追问；>128 token 桶召回 54.4% |
| ② | **多标签逐类阈值（按 §四 协议重选）** | 已实测宏 F1 0.6481 → 0.7834、高音 0 → 0.5161，不动权重、约 1 小时；仅影响归因侧 |
| ③ | **高音类别 C1（合并刺耳→清晰度）或 B（加权重训）** | 消除"五类中一类学不会"的可见硬伤 |
| ④ | **四五星音质评论开采** | 闸门中最贵、最不可控（1 天时间盒偏乐观）；超时走 §8.1 的降级出口 |
| ⑤ | 基座对比 / 非音频子集误报率 / 数据效率单值 | 成本低、叙事有用，排在闸门条件之后 |

**两点提醒**：仅做 ①②③ 时，第 (1) 条闸门大概率未达——§七 降级分支已写出口，设计自洽；"逐类阈值 0.7834"与"二分类 0.72"是两个不同指标，**不可互相顶替**。
