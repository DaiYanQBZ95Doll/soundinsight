# W1 长文本截断修复：变体对比（阶段结论）

> **DoD（冻结清单 §二 W1）**：截断桶（>128 token）召回 **≥70%**；四方案对比表 + 修复前后对比表。
> **评测口径**：无泄漏留出集 `val_v3_test`（n=10,000，正例 128，来自当前标签集的 20% 留出划分）。
> **重要前提（2026-09-30 发现）**：`val_v2` **不能**再用于评估"用当前标签训练的新模型"
> ——它与当前训练划分重叠 79.5%（正例 78.9%），会造成记忆虚高（实测一次得 0.9126，已作废）。
> **状态**：三变体已测，**验收线未达**；512 变体训练中。

---

## 一、四个变体的定义

| 变体 | 做法 | 是否重训 |
|---|---|---|
| **A** `truncate@128` | v1 原方案：训练与推理均截断到 128 token | 是（对等基线） |
| **B** `truncate@256` | 训练与推理放宽到 256 token | 是 |
| **C** `segment@128` | **不重训**：推理时把长文本切成 128 token 窗口（stride 64），取**窗口最大概率** | 否（复用 A 的模型） |
| **D** `truncate@512` | 训练与推理放宽到 512 token | 是（训练中） |

## 二、结果（val_v3_test，阈值 0.5，除注明外）

| 变体 | 整体 P | 整体 R | 整体 F1 | ≤64 桶 F1／R | 65–128 桶 F1／R | **>128 桶 F1／R** |
|---|---|---|---|---|---|---|
| A `truncate@128` | 69.7% | 71.9% | 0.7077 | 0.7523／83.7% | 0.7792／78.9% | **0.5676／51.2%** |
| B `truncate@256` | 74.8% | 69.5% | **0.7206** | 0.7664／83.7% | 0.7826／71.1% | **0.5915／51.2%** |
| C `segment@128`（0.5） | 47.7% | 82.0% | 0.6034 | 0.7523／83.7% | 0.7792／78.9% | **0.4198／82.9%** |
| C `segment@128`（tune 选 0.8） | 53.3% | 70.3% | 0.6061 | 0.7475／75.5% | 0.7353／65.8% | **0.4308／68.3%** |
| D `truncate@512` | — | — | — | — | — | （训练中） |

**关键对照**：A 与 B 的截断桶 **TP21/FN20 完全一致**——放宽到 256 对截断桶**毫无改善**。

## 三、为什么 256 不够：token 长度分布（val_v3_test 实测）

| 区间 | 条数 | 占比 |
|---|---|---|
| ≤128 token | 8,066 | 80.7% |
| 129–256 | 1,174 | 11.7% |
| 257–512 | 548 | 5.5% |
| >512 | 212 | 2.1% |

超过 128 token 的 1,934 条中，**760 条（39.3%）超过 256 token**；P95=333、P99=694、最长 3,509。
→ **截断桶里近四成文本对 256 窗口仍然过长**，这解释了 B 的无改善。

## 四、切窗（变体 C）的发现：召回换精确率，且单一阈值不可兼顾

- 取窗口最大值把截断桶召回从 **51.2% 提到 82.9%（@0.5）**，但整体精确率从 69.7% 掉到 47.7%（FP 40→115）；
- 在 tune 上重选阈值到 0.8 后：截断桶 R 回落到 68.3%、F1 0.4308，短文本桶反而受损（≤64 桶 R 83.7%→75.5%）；
- **根因**：max 聚合抬高了长文本的分数分布，**一个全局阈值无法同时服务长文本与短文本**。
- 可行的改进方向（尚未做）：① 长文本走切窗、短文本走截断的**混合策略**；② top-k 均值或分位数聚合（比 max 稳）；③ **按长度分档的各档阈值**。

## 五、当前判定与下一步

- **DoD 未达**：截断桶召回最高 82.9%（切窗@0.5）但同档 F1 仅 0.4198；兼顾 F1 时召回 68.3%（略低于 70% 线）。
- **下一步（按性价比）**：
  1. **变体 D（512）**：训练中，若截断桶召回 ≥70% 则直接达标（代价是训练/推理变慢）；
  2. **混合策略**：>128 token 才切窗，其余走截断，并用**分档阈值**（tune 上分别选）；
  3. 若仍不达标 → 按采纳闸门降级分支：**如实报"截断桶召回 68–83%（取决于聚合方式），未达 70% 验收线"**，并在局限章节写明。

> 口径提醒：本表所有数字均为 `[v2]`，样本为当前标签集的留出划分，**与 v1 的 val_v2 数字不可直比**。
