# W1 长文本截断修复：变体对比（阶段结论 v2）

> **DoD（冻结清单 §二 W1）**：截断桶（>128 token）召回 **≥70%**；四方案对比表 + 修复前后对比表。
> **评测口径**：无泄漏留出集 `val_v3_test`（n=10,000，正例 128）；阈值一律在 `val_v3_tune` 上选。
> **前提**：`val_v2` 不能用于评估当前标签训练的模型（重叠 79.5%，见 §四）。
> **当前判定**：**DoD 未达**——但证据链完整，且**推翻了"截断是主因"这一 v1 前提**。

---

## 一、变体与结果（val_v3_test）

| 变体 | 做法 | 整体 F1 | ≤64/≤128 桶 | **>128 token 桶（截断桶）** |
|---|---|---|---|---|
| **A** `truncate@128` | v1 原方案 | 0.7077 | 0.7523／R 83.7% | F1 0.5676／**R 51.2%**（TP21/FN20） |
| **B** `truncate@256` | 窗口放宽 | **0.7206** | 0.7664／R 83.7% | F1 0.5915／**R 51.2%**（TP21/FN20） |
| **D** `truncate@512` | 窗口再放宽 | 0.7100 | 0.7551／R 75.5% | F1 0.6364／**R 51.2%**（TP21/FN20） |
| **C** `segment@128`（0.5） | 不重训，切窗取最大概率 | 0.6034 | 0.7523／R 83.7% | F1 0.4198／**R 82.9%** |
| **C'** `segment@128`（tune 0.8） | 全量切窗 + 全局阈值 | 0.6061 | 0.7475／R 75.5% | F1 0.4308／**R 68.3%** |
| **E** 混合（短档截断＋长档切窗）**约束式**选阈值 | 先约束长档 tune 召回 ≥70%，再最大化整体 F1 | 0.6196 | 0.7449／R 83.9% | F1 0.4308／**R 68.3%** |

阈值选择记录：A–D 用 0.5（D 同口径对照）；C' 为全量切窗下 tune 选中的 0.8；E 为约束式选中 **短档 0.2／长档 0.8**。

## 二、三个关键结论

### 结论 1：**截断不是截断桶召回的主因**（推翻 v1 前提）
窗口 128 → 256 → 512，截断桶召回**始终是 51.2%**，且 **TP21/FN20 完全相同**。
若截断是主因，放宽窗口应带来召回提升；实测**零提升**（512 甚至只提升 F1、不动召回）。
→ v1 叙事中"长文本被截断以致漏检"的解释**不成立**（至少不是主要机制）。

### 结论 2：信号存在于**子片段**，单次前向会把它平均掉
同一模型（`max_len=128` 训得）改为**切窗**推理后，截断桶召回 **51.2% → 82.9%**。
说明这些长评论里的差评证据集中在某个片段，而单次编码会把整篇"平均"成非负面。

### 结论 3：代价是精确率，且**无法用单一阈值兼顾长短文本**
切窗（max 聚合）抬高长文本分数分布：整体精确率 69.7% → 47.7%（FP 40 → 115）；
改用全局阈值 0.8 后短文本桶受损（R 83.7% → 75.5%）；
用**分档阈值**（变体 E，约束长档召回 ≥70%）后短文本恢复（R 83.9%），
但 test 长档召回只有 **68.3%**（tune 上 71.8%——样本仅 41 条正例，波动大），
整体 F1 仍只有 0.6196（对比 B 的 0.7206）。
→ **在当前模型与聚合方式下，召回与精确率存在硬权衡**：要 ≥70% 长档召回，整体 F1 会落到 ~0.62。

## 三、DoD 判定与如实结论

| 判定项 | 结果 |
|---|---|
| 截断桶召回 ≥70% | **未达**（最好 68.3%，且是概率权衡下的上限附近） |
| 四方案对比表 | **已具备**（A/B/C/D + 两个改良变体 C'/E） |
| 修复前后对比表 | **已具备**（A 为基线，B/D/C/C'/E 为对照） |

**如实结论（可直接写入材料）**：
> "我们把长文本问题从'以为是被截断'改判为'**是子片段信号被整篇平均**'：窗口从 128 放宽到 512，
> 截断桶召回**一分未涨**（51.2%）；改用切窗推理后召回升到 **82.9%**，但精确率代价使整体 F1 从 0.72 降到 0.60。
> 在'长档召回 ≥70%'的约束下，可做到 68.3%（略低于验收线）。**该验收线未达，已如实记录。**"

## 四、口径与前提（不可省）

1. 全部数字为 `[v2]`（当前标签集的留出划分），与 v1 的 `val_v2` 数字**不可直比**；
2. **`val_v2` 不可用于评估当前标签训练的模型**：它与当前 80% 训练划分重叠
   **15,891/20,000（79.5%）**，含正例 **198/251（78.9%）**——在它上面评估会因记忆虚高
   （实测一次得 F1@0.5 = 0.9126，**该数字作废**）；
3. token 长度分布（val_v3_test）：≤128 **80.7%**；129–256 **11.7%**；257–512 **5.5%**；>512 **2.1%**；
   超长部分中 **39.3% 超过 256 token**（P95=333、P99=694、最长 3,509）。

## 五、下一步（若继续投入）

1. **架构级修复**（推荐）：切片级打分 + 学习式聚合（如 top-k 均值/注意力池化），而非 max；
2. 用**长文本专项训练**（在长评上过采样）替代单纯放宽窗口；
3. 若时间不允许，按采纳闸门如实记录"未达标"并在局限章节给出机制解释（本页即为素材）。
